# EDURange Cloud Modules

What makes EDUrange Cloud so powerful is its fully modular deployment system. To set up EDUrange Cloud, a user only needs to install the base framework, which includes the instance-manager, ingress controller, and other essential components. After that, the user can choose additional modules to enhance their EDUrange Cloud experience. Adding a module is as simple as deploying a new pod to the cluster. Creating a module is just as easy; all you need is a dockerized version of the module you want to add.

## Module Architecture

Modules in EDURange Cloud are designed to be self-contained and easily deployable. Each module is packaged as a Docker container that can be deployed to the Kubernetes cluster. Modules can be standalone applications or integrated with the WebOS to provide additional functionality.

### Types of Modules

1. **WebOS Applications**: These modules are integrated directly into the WebOS interface, appearing as applications that users can interact with.

2. **Challenge Types**: These modules provide different types of cybersecurity challenges, such as web vulnerabilities, network analysis, or reverse engineering.

3. **Infrastructure Services**: These modules provide additional services to the cluster, such as monitoring, logging, or authentication.

## Creating Custom Modules

Users can create their own modules to extend the functionality of EDUrange Cloud. Here's a basic outline of the process:

1. **Create a Docker Container**: Package your application or service as a Docker container.

2. **Define Kubernetes Resources**: Create the necessary Kubernetes resources (Deployment, Service, etc.) to deploy your module.

3. **Integration with WebOS (Optional)**: If your module should be accessible through the WebOS interface, create the necessary configuration in the `apps.config.js` file.

4. **Deploy to Cluster**: Deploy your module to the Kubernetes cluster using `kubectl apply`.

### Example: Simple Web Application Module

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-custom-module
spec:
  replicas: 1
  selector:
    matchLabels:
      app: my-custom-module
  template:
    metadata:
      labels:
        app: my-custom-module
    spec:
      containers:
      - name: my-custom-module
        image: my-registry/my-custom-module:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: my-custom-module-service
spec:
  selector:
    app: my-custom-module
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

## Module Management

Modules can be managed through the EDURange Cloud dashboard or directly using Kubernetes commands. The dashboard provides a user-friendly interface for deploying, updating, and removing modules, while Kubernetes commands offer more flexibility for advanced users.

### Dashboard Management

The dashboard allows users to:
- Browse available modules
- Deploy modules with custom configurations
- Update existing modules
- Remove modules that are no longer needed

### Command-Line Management

Advanced users can manage modules directly using Kubernetes commands:

```bash
# Deploy a module
kubectl apply -f module.yaml

# Update a module
kubectl apply -f updated-module.yaml

# Remove a module
kubectl delete -f module.yaml
```
